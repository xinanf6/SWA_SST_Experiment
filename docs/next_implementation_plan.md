# 诊断完成后的模型与训练实施计划

依据：`output/analysis/regional_diagnostics_window_qc/`训练期诊断、已冻结的预处理版本2，以及最初的实验方案。当前阶段不实现无训练基线。

## 1. 诊断证据与实现决策

| 已核对的结果 | 对下一步的约束 |
| --- | --- |
| SST月均值2月18.27℃、8月10.57℃ | 各模型使用全年训练数据，最终按南半球四季评价；不按季节分别训练四套网络 |
| 训练P90为0.08126817℃/km；强锋面积1月6.88%、6月12.45% | DFA要同时保留方向和强度；温度主指标之外，单独评价真值强锋区与梯度结构 |
| 平均表层流速0.34017 m/s | 对应约29.4 km/day的特征平流距离，但不是逐粒子位移观测；保留DSPG动力启发主干，并检查缓冲区附近误差 |
| 区域月均MLD约14.86—75.85 m；训练格点日中位数22.660013 m | 保留动态MLD及热力编码，评价时按冻结中位数划分浅深组，分组使用t−1的MLD |
| 12月平均热力日倾向+0.2651℃/day，6月−0.0567℃/day；观测日变化绝对值月均约0.277—0.319℃/day | 热力增量有明显季节差异，CH收益需按提前期、季节和浅深层检验；不能预先认定其有效 |
| 区域全年平均净热通量−2.0848 W/m²，而平均热力倾向+0.0680℃/day | 平均Q/h不等于平均Q除以平均h；不能因此翻转通量符号。应结合Q与1/h的共同变化解释，不据此计算热力贡献比例 |

强锋面积约10%部分来自P90阈值定义，不能作为锋面机制有效性的证据。上述季节差异只形成待检验假设。29.4 km/day也意味着现有约0.25°缓冲区不能被解释为覆盖三日物理输运范围；主核心区保持不变，补充分析核心边缘带误差。

## 2. 固定协议与输入输出

- 数据目录：`output/processed_window_qc/`；仅接受该批次READY、统计量及运行身份。
- 训练/验证/测试样本：3580/704/714；所有模型使用同一质量筛选后的索引。
- SST和锋面历史：t−13…t；环境及热力历史：t−14…t−1；输出t+1…t+3。
- 保留270×250输入和260×240核心区域；温度损失在核心海洋域归约，梯度在完整输入求导后于核心有效模板归约。
- 有效厚度下限3 m，净表面热量直接计算，H_k=kΔT_heat,t−1；保持最初方案的短波、衰减及直接三提前期输出约定。
- 网络输入使用训练期标准化值；最终温度、显式增量和网络残差使用℃。

原DSPG位于`H:/fxa/DSPG/DSPG_code/model.py`，已确认可以读取。其辅助监督比较学习位移与标准化海流，属于原有启发式约束；不得将输出位移直接标为m/s。移植时记录源文件SHA256，显式固定原有扩散模式、尺度及残差开关，不依赖原项目全局config或绝对数据路径。

## 3. 第一阶段：接通训练闭环（优先级最高）

建议新增`sst_training/`，职责如下：

| 模块 | 职责及交付 |
| --- | --- |
| `data.py` | 将PreparedSSTDataset包装为Torch Dataset；保留日期与完整分区顺序；Windows worker只重新打开只读memmap |
| `models/dspg.py` | 移植并锁定原空间编码、动力启发、双流时序及解码结构；移除原项目全局配置依赖 |
| `models/encoders.py` | 两层3→16→32的锋面/热力编码与锋面门控 |
| `models/predictor.py` | 统一C0/CF/CH/CFH开关及℃输出；管理最后SST、H和R的组合 |
| `losses.py` | 面积加权温度MSE、原辅助损失、可微米制梯度损失 |
| `engine.py` | AMP、梯度累积、裁剪、训练/验证循环、早停及检查点 |
| `predict.py` | 将已训练模型逐日起报预测流式写为统一NetCDF，直接交给sst_analysis |
| `__main__.py` | `smoke`、`benchmark`、`train`、`predict`入口；配置与日志分离 |

先实现C0闭环：基础编码加共享热力编码，预测残差，不启用DFA或显式H。随后接入同一代码路径上的CF、CH、CFH，避免四份独立训练脚本。

若解码器输出无量纲残差r，则R=σ_SST·r，不能再加SST均值。预测为T_t+R或T_t+H+R。原七变量直接输出模型仍按μ_SST+σ_SST·z反标准化。单位组合必须单独测试。

短程验收：4组模型都通过真实网格前向与反向；所有分支收到有限梯度；小型训练子集能够降低训练损失；检查点恢复后继续训练；预测文件通过现有日期、坐标、单位及身份检查。小样本过拟合只检验实现，不作为模型效果。

## 4. 第二阶段：损失与真实算力验收

维持最初损失结构：L=L_SST+0.1L_aux+0.1(L_vec+0.5L_mag)。

- L_SST在反标准化℃空间计算面积加权MSE，三个提前期等权。
- 梯度采用可微球面中心差分，和现有NumPy实现对齐；使用冻结训练梯度尺度归一化，不拟合验证/测试尺度。
- 真值强锋点权重3，其余1；加权损失除以实际有效权重和。梯度向量MAE按两个分量平均，与评价器定义一致。
- DFA关闭时不加入对应梯度结构损失；四组保留一致的主损失、原辅助约束和模型选择准则。DFA因素包含编码、门控与梯度损失，后续内部消融再拆开。
- 逐项记录原始损失、加权损失及其梯度量级。首个验证阶段如需调整权重，须对四组统一冻结后重跑，不能按测试结果或模型分别调权。

当前环境实测可导入PyTorch 1.12.0，CUDA可用，GPU为RTX 3060。先使用兼容现有环境的torch.cuda.amp，不为本阶段强制升级环境。

以真实全域样本、最复杂CFH做基准：预热后测100个完整前向/反向批次，包含读取；记录峰值显存、训练/验证耗时、吞吐量及参数量。比较batch=2+累积2与batch=4+累积1，保持有效batch=4。worker从0、2中实测选择，显存允许再比较4；不预先采用梯度检查点，因为它可能增加总耗时。

训练初值：AdamW、lr=1e−3、weight_decay=1e−5、最多50轮、早停8轮、平台3轮后学习率减半、梯度裁剪1.0。按验证集核心域物理单位SST MSE选择best；训练/验证不计算逐批骨架锋线，锋线留到导出的预测统一评价阶段。

## 5. 第三阶段：先完成核心训练对照

| 模型 | 基础7通道 | 共享热力编码 | DFA | 显式H | 输出 |
| --- | --- | --- | --- | --- | --- |
| 七变量原DSPG | 是 | 否 | 否 | 否 | 直接温度 |
| C0 | 是 | 是 | 否 | 否 | T_t+R |
| CF | 是 | 是 | 是 | 否 | T_t+R |
| CH | 是 | 是 | 否 | 是 | T_t+H+R |
| CFH | 是 | 是 | 是 | 是 | T_t+H+R |

四个核心模型共享同一基础和热力信息；锋面是相同SST的确定性派生。第一轮使用种子2026，先完成C0和原DSPG，再完成CF、CH、CFH。验证实现及收敛后，5组补种子2027、2028，共15次核心完整训练；七变量残差DSPG单种子作为补充控制，共16次。

同种子共享主干初始权重及样本顺序，新增模块使用独立随机流，避免开关改变随机数消费顺序。训练shuffle只用于训练分区，不使用空间翻转等需要同步变换向量分量的增强。

完整运行时间按真实测得的每轮训练/验证耗时估算，不沿用合成0.8秒/批或预设早停轮数。单卡排队执行，先完成首种子核心证据再扩展实验矩阵。

## 6. 第四阶段：统一评价与机制解释

- 首先评价验证集三个提前期及8个固定分组。开发阶段不查看测试分数调结构；方案冻结后，统一导出测试期全部714个起报日预测。
- 主表报告3种子均值和标准差；温度、强锋区及梯度指标作为主证据，原始骨架位置指标作补充。
- 对比CF−C0、CH−C0、CFH−C0以及CFH与两个单机制模型，采用已有同日起报30天块、2000次配对Bootstrap。不同种子不能作为额外独立日期合并。
- 冬季/强锋组重点检验DFA；暖季/浅MLD组重点检验热力结构。这是预先指定的分析方向，不要求结果必须符合该方向；报告所有季节和三个提前期。
- 年平均Q与热力倾向异号通过分月、浅深层和Q与1/h共同分布解释。H、R的符号及幅度、相互抵消情况只用于分解诊断，不能解释为真实过程贡献比例。
- 温度变化误差(预测−T_t)−(参考−T_t)与普通温度误差完全相同，不重复作为独立证据；补充高变化样本误差和变化符号命中率时，阈值只由训练期确定。
- 若CFH仅优于两个单机制模型，可称联合改善。若要声称超加性协同，新增四模型共享重采样的交互检验I=E_CF+E_CH−E_C0−E_CFH；不能拼接两模型置信区间推导交互结论。
- 固定核心区主指标保持不变；补充核心边缘带误差，明确现有缓冲区不能消除所有三日边界影响。

预测文件保存`predictions(origin,lead,latitude,longitude)`、三日目标日期、完整坐标、℃单位及运行身份。分解量H、R、最后SST单独记录，检查重构恒等式。仅对已训练模型评价，不另生成无训练预测文件。

实验继续采用事后产品开展历史回报，论文结论限定为相对OSTIA分析参考的预测能力；没有独立观测时，不宣称独立卫星真值验证或实时业务能力。

## 7. 后续消融与论文材料

核心结果稳定后，再依次运行：梯度直接拼接、容量匹配普通分支、CFH去掉梯度损失、CH动态MLD换训练月气候态。先单种子，涉及主结论再补另外两种子。

ConvLSTM、CResU-Net以及SSTODE适配版在核心闭环和真实排期明确后接入。前两者共享基础及热力信息，SSTODE需另行核查官方实现后制定适配说明；本阶段不宣称已完成复现。

按最初方案固定强锋、高温度变化、强热力倾向三类案例，仅依据参考数据选择、至少间隔14天，不按模型表现挑选。高变化及强热力事件阈值与筛选规则在查看测试预测之前冻结。

交付顺序：

1. 开发第1—2天：Torch数据适配、DSPG源代码审计与C0闭环。
2. 第3天：4组前后向、损失单位、差分、掩膜和检查点验收；真实吞吐基准。
3. 第4天起：首种子核心训练和验证；根据实测耗时形成GPU排队表。
4. 通过首轮验收后：补多种子、关键消融及外部训练参照，最后统一测试与案例图。

开发日程为预计工期，完整训练完成日期以真实基准为准。每次运行保存配置、种子、源代码版本、数据身份、best/last检查点、优化器/调度器/AMP/RNG状态、逐轮日志和预测文件。恢复默认以轮次边界为单位；数据身份或结构配置不一致则拒绝恢复。
